# Семантический анализатор для языка Funny (HW3)

## Описание проекта

Реализация семантического анализатора для выбранного подмножества языка Funny. Анализатор обходит построенное парсером абстрактное синтаксическое дерево (AST) с помощью паттерна Visitor (`ASTVisitor`), выполняет двухпроходную проверку модулей (сначала регистрация сигнатур функций, затем анализ контрактов и тел), проверяет области видимости, типы и сигнатуры вызовов и собирает все независимые ошибки без остановки после первой.

На выходе формируется аннотированное AST (каждый узел выражения получает вычисленный тип `exprType`), пригодное для дальнейшего построения IR и кодогенерации.

**Особенности реализации:**
- **Двухпроходный анализ модуля:** поддерживаются несколько функций в одном файле, прямая рекурсия и вызовы функций, объявленных ниже по тексту.
- **Области видимости:**
    - `requires` видит только входные параметры функции;
    - `ensures` видит входные параметры и переменные `returns` (без `uses`);
    - тело функции и `invariant` видят параметры, `returns` и локальные переменные `uses`;
    - затенение имён из внешних областей видимости запрещено.
- **Неизменяемость входных параметров:** запись во входные параметры (включая параметры-массивы) запрещена.
- **Вывод типов локальных переменных (`uses`):** тип выводится по первому корректному присваиванию (включая кортежное). Ошибочные выражения, вызовы и обращения к массивам получают тип `ERROR` и не фиксируют тип переменной. Использование переменной до вывода типа или отсутствие корректного присваивания считается ошибкой.
- **Строгая типизация:**
    - операторы порядка (`<`, `<=`, `>`, `>=`) применимы только к `int`;
    - условия `if`, `while`, контракты `requires`/`ensures`/`invariant`, а также `assert`/`assume` требуют логический тип (`bool`);
    - при вызове неизвестной функции аргументы всё равно обходятся и проверяются.
- **Коды возврата и потоки вывода:** чистое аннотированное AST выводится в `stdout`, диагностика с позициями `[line:col]` — в `stderr`. При любых лексических, синтаксических, семантических ошибках или несовпадении snapshot программа завершается с кодом `1` (при успехе — `0`).

## Требования

- Java 17+ (проверено на JDK 21)
- Утилита `make`
- `bash` (для запуска набора автотестов)
- `lib/java-cup-11b.jar` и `lib/jflex.jar` *(включены в репозиторий)*

## Структура проекта

- `Makefile` — сборка (`compile`), очистка без удаления эталонов (`clean`), перегенерация эталонов (`snapshots`) и запуск всех тестов (`test`).
- `run_tests.sh` — скрипт автоматического прогона позитивных (сверка AST и `exit 0`) и негативных тестов (проверка `exit != 0`, числа ошибок, позиций и текста диагностик).
- `src/lexer/lexer.jflex` — спецификация лексера JFlex.
- `src/parser/parser.cup` — грамматика парсера CUP (0 конфликтов, 0 предупреждений).
- `src/ast/` — узлы AST (`ProgramNode`, `FunctionDeclNode`, `TupleAssignNode`, `UnaryOpNode`, `BoolLitNode` и др.) и интерфейс `ASTVisitor`.
- `src/semantic/` — `SemanticAnalyzer`, `Scope`, `SymbolInfo`.
- `src/Main.java` — точка входа (лексер -> парсер -> семантический анализ -> вывод/сверка AST).
- `tests/` — позитивные тесты с эталонными `.ast` снимками и негативные тесты диагностик.

## Поддерживаемое подмножество Funny и ограничения

### Поддерживаемые конструкции
- **Модули из нескольких функций** с опциональным ключевым словом `function`.
- **Заголовок функции:** обязательные аннотации типов для входных параметров и непустого списка `returns`, опциональные контракты `requires` и `ensures`, опциональный блок локальных переменных `uses` (аннотация типа опциональна).
- **Типы:** `int`, `bool`, `int[]`, `bool[]`.
- **Операторы:** обычное присваивание (`x = e;`), кортежное присваивание для функций с несколькими возвращаемыми значениями (`u, v = pair(a, b);`), индексирование и обновление массивов (`a[i]`, `a[i] = v;`), `if (...) { ... } [else { ... }]`, `while (...) [invariant ...] { ... }`, `assert`, `assume`.
- **Выражения:** арифметика (`+`, `-`, `*`, `/`, `%`, унарный `-`), сравнения (`==`, `!=`, `<`, `<=`, `>`, `>=`), логика (`true`, `false`, `and`, `or`, `not`), вызовы функций и встроенная функция `length(a)` с сигнатурой `(int[]) -> (int)`.

### Известные ограничения подмножества
- Не поддерживаются кванторы `forall` / `exists`, пользовательские формулы и логическая импликация `->`.
- Анализ определённости присваивания по всем путям потока управления (definite assignment) не выполняется в рамках HW3.

## Сборка и запуск

1. **Очистка сгенерированных и скомпилированных файлов** *(эталонные `tests/*.ast` сохраняются)*:
```bash
make clean
```

2. **Полная компиляция:**

```bash
make compile
```

3. **Запуск всех позитивных и негативных тестов:**

```bash
make test
```

4. **Перегенерация эталонных .ast снимков для позитивных тестов:**

```bash
make snapshots
```

5. **Ручной запуск на отдельном файле:**

```bash
java -cp "lib/java-cup-11b.jar:src" Main tests/test_positive.txt
java -cp "lib/java-cup-11b.jar:src" Main tests/test_positive.txt tests/test_positive.ast
```
